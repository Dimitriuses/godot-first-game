# Audio render

Every sound in the game, synthesised from nothing:

```sh
python tools/audio-render/make_sounds.py            # render and report, write nothing
python tools/audio-render/make_sounds.py --write    # write assets/audio/*.wav
python tools/audio-render/make_sounds.py --preview  # also out/preview.png
```

Seventeen 16-bit mono WAVs at 44.1 kHz, about 310 KB in total. They are **committed**, the
same way the die frames are: the tool is the source, the files are the build, and the build
is checked in so the game runs without it. `out/` is gitignored.

Needs numpy, and Pillow for `--preview`. Both are already required by other tools here.

## Why synthesised

Everything in this repository that is not code is generated by a committed tool. Audio had
the same problem the die art had, and the same answer solves it: a generated sound has a
provenance story of one line, can be re-tuned by editing a number rather than re-recording,
and cannot quietly acquire a licence nobody read.

A die clack is **modal synthesis** — a short band-limited noise transient for the strike,
plus five exponentially decaying partials at inharmonic ratios for the body. That is what a
small hard object actually does: a few strong modes and no harmonic series. It is why these
read as objects rather than as beeps.

## What the numbers mean

A dry run prints length, peak, RMS and **spectral centroid** — one number for how bright a
sound is, and the one that catches mistakes. The first version of this tool filtered noise
with a one-pole, which is 6 dB/octave, and a "lowpassed" burst is still mostly hiss: every
sound came out with a centroid near 6 kHz whatever its modes were, and they all sounded the
same. Filtering in the frequency domain fixed it. Current values, which are what a change
should be checked against:

| | centroid |
|---|---|
| `die_hit_0..3` | 2.6–3.7 kHz, rising across the four variants |
| `die_land` | 0.7 kHz — a dull settle |
| `die_roll` | 3.2 kHz — four soft strikes, a rattle in place |
| `spawn` | 0.5 kHz — a soft set-down |
| `ui_open` / `ui_close` | 0.6 / 0.8 kHz — tones, not clicks |
| `throw_all` | 2.5 kHz — rumble plus clatter |

`--preview` writes a waveform and spectrogram for each, drawn with Pillow rather than
matplotlib so the tool needs nothing this repository does not already use.

## Determinism

Two runs produce byte-identical files, and the tool is written so they must. Each sound is
seeded from `zlib.crc32` of its own name — **not** `hash()`, which Python randomises per
process, and which quietly gave a different set of files on every run until it was caught
by comparing two.

## Mixing

The peaks in the `SOUNDS` table are relative levels, not decoration: a die landing should
not be as loud as the whole board being thrown. `Sfx.cs` mixes everything through one bus
at `-7 dB` and adds nothing per call site, so what is set here is what is heard. Policy
that is *not* here — how often a sound may repeat, how many can overlap, how loudness
follows impact speed — lives in `scripts/Sfx.cs`.
